# ADR-0001: 采用六边形架构

## 状态
已接受

## 背景
我们需要将 OpenAkita (OAK/LangCrew) 的企业级多 Agent 协作能力与 GenericAgent 的极简自我进化特性融合在一起。两个项目有着截然不同的架构风格：
- GenericAgent：单体架构，约 3K 行核心代码，强调极简和自我进化
- OpenAkita/LangCrew：基于 LangGraph 的多 Agent 框架，强调协作和可视化

## 决策
我们采用 **六边形架构（Hexagonal Architecture）**，也称为端口与适配器模式。

## 理由
1. **解耦性**：内核与外部依赖通过端口隔离，便于独立演进
2. **可测试性**：每个组件可独立测试
3. **可替换性**：可随时替换某个适配器而不影响其他部分
4. **渐进式迁移**：可逐步将两个项目的功能迁移到新架构
5. **保留各自优势**：
   - GenericAgent 的原子工具和自我进化机制作为适配器保留
   - LangCrew 的多 Agent 协作作为新模块接入

## 结果
- 建立了清晰的分层结构：Core → Ports → Adapters
- 内核（Core）只包含纯业务逻辑，无外部依赖
- 端口（Ports）定义接口契约
- 适配器（Adapters）实现与外部系统的集成

## 代价
- 增加了抽象层的复杂度
- 需要维护更多的接口定义
